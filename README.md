# QA Flow (канбан для команды)

Состояние: этап 2 из 10. Пока в приложении только вход по логину и паролю, смена пароля и проверка связи с базой. Доски появятся на этапе 3.

## 1. Заполнить настройки

Открой `src/config.ts` и замени два значения:
- `SUPABASE_PUBLISHABLE_KEY`: публичный ключ (`anon` или `publishable`) из Supabase → Project Settings → API;
- `LOGIN_DOMAIN`: домен, который ты использовала в адресах пользователей (всё после `@`).

Секретный ключ (`service_role` / `secret`) сюда нельзя. Публичный можно: данные защищены правилами RLS в базе.

## 2. Выложить на GitHub Pages

1. Репозиторий должен быть **публичным** (Pages из приватного требует платного тарифа). В коде нет секретов, только публичный ключ.
2. Отправь репозиторий на GitHub (папка `.github` с автопубликацией входит в него):
   ```
   git init
   git add .
   git commit -m "Этап 2: каркас приложения и вход"
   git branch -M main
   git remote add origin https://github.com/<твой-логин>/<репозиторий>.git
   git push -u origin main
   ```
3. В репозитории: **Settings → Pages → Build and deployment → Source: GitHub Actions**.
4. Вкладка **Actions**: дождись зелёной галочки у «Deploy to GitHub Pages» (1-2 минуты).
5. Адрес приложения: `https://<твой-логин>.github.io/<репозиторий>/`

Любое следующее изменение в ветке `main` публикуется автоматически. Откат: в Git вернуть предыдущий коммит.

## 3. Запуск у себя (необязательно)

Нужен Node.js 20+.
```
npm install
npm run dev
```
Сборка для проверки: `npm run build`.

## Что проверить после публикации

1. Открывается экран входа (без VPN).
2. Вход твоим логином и паролем: видно «Основа готова», твоё имя и «админ».
3. «Связь с базой» показывает «в порядке (досок: 0)».
4. «Сменить пароль» работает, после выхода вход с новым паролем проходит.
5. С неверным паролем появляется «Неверный логин или пароль».
6. Вход у остальных трёх участников.

## Известные ограничения

- Код написан, но не собирался и не запускался в моей среде (нет доступа к npm). Первая сборка в GitHub Actions станет реальной проверкой. Если она упадёт, пришли текст ошибки из вкладки Actions.
- Файла `package-lock.json` нет: он создаётся при первом `npm install`. После первого локального запуска его стоит закоммитить.
