# Сценарные проверки интерфейса (без Supabase)

Собирают **настоящий код приложения** (`src/`) и прогоняют его в Chromium на поддельной базе в памяти:
создание досок, колонок, карточек, свойств, поиск, фильтры, представления, перенос карточек и колонок,
конфликты правок, realtime, экспорт XLSX и CSV, архив и корзина, базы знаний, статистика, тема, вход и выход (46 шагов).

Три библиотеки (`@supabase/supabase-js`, `@tanstack/react-query`, `@dnd-kit`) и `fractional-indexing` заменены простыми
версиями из `shims/`, а запросы к базе обслуживает `shims/fake-supabase.js`. Поэтому это проверка **логики интерфейса**.
Проверку настоящих правил доступа (RLS) и самой базы она не заменяет: для этого есть SQL-тесты (`tools/test/`) и приёмка
на реальном проекте (`docs/02-acceptance.md`).

## Запуск

```
cd tools/e2e
npm install
npx playwright install chromium
npm test
```

Перед этим в корне репозитория должен быть выполнен `npm install` (нужны React и DOMPurify).
Задержку сети можно имитировать: `LATENCY=80 npm test` (миллисекунды на каждый запрос, лучше проверять и так, и так).
Успех: «Итог: 46 из 46 шагов прошли» и «ОШИБКИ БРАУЗЕРА: нет». Скачанные во время прогона файлы экспорта и скриншот
складываются во временную папку, её путь печатается в конце.

Переменные окружения для нестандартных сред: `PLAYWRIGHT_MODULE`, `ESBUILD_MODULE`, `CHROMIUM_PATH`, `NODE_PATH`.

## Что здесь не проверяется

Само перетаскивание мышью (проверяются обработчики, которые приложение передаёт библиотеке), настоящий realtime Supabase,
правила доступа и триггеры в базе, работа без сети, мобильные экраны.
